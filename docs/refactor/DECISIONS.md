# 重构决策记录

## D-001：先外部备份，再建立 Git

当前目录无版本控制。先创建完整项目外备份，随后初始化 Git 并提交基线。原因是 Git ignore 排除了历史产物，而外部备份可以恢复包括 `Objects/`、`Listings/` 在内的全部状态。

## D-002：不使用 ARM Compiler 6 替代 ARMCC 5 验收

本机只有 armclang 19；工程和闭源 `.lib` 明确面向 ARMCC 5。ARM Compiler 6 可用于有限语法诊断时也不能产生 `BUILD_VERIFIED` 结论。

## D-003：历史构建只作参考

历史日志路径和时间不属于本次工作区构建。资源数据、警告和哈希记录为基线信息，但不会写成当前构建成功。

## D-004：硬件敏感实现冻结

超声波激励/捕获、SysTick、UART ISR、Flash 物理擦写、软件 I2C 不做实质改写。先在外围建立窄接口与静态契约检查；若无 ARMCC 5 反汇编证据，保持函数体。

## D-005：测试接缝以生产代码为唯一实现

对 checksum、序列化、滤波、O2/流量/PWM 建立纯函数时，生产固件和主机测试必须调用同一实现。禁止在测试中复制一份公式自证。

## D-006：保留异常历史共享

`IsAbnormalFluctuation` 的两个静态值由 O2 和流量共同使用。尽管可疑，本轮把它视为兼容状态；除非重构前后序列测试能证明完全等价，否则不拆成两个状态。

## D-007：实际周期优先于名称和注释

`Flag20ms` 阈值为 100，`Flag100ms` 也为 100。重构保持两个任务实际约 100 ms 的行为，只在文档说明命名不符。

## D-008：对不确定的 UB 不做“顺手修复”

未初始化局部变量、可能除零和越界风险先记录。修改它们会改变真实产品历史行为，必须放到独立 bug 修复项目并配合硬件/产品输入验证。

## D-009：无本机 C 主机编译器时执行生产 C AST

当前环境没有 GCC/MSVC/Clang 主机工具链。测试使用已有 `pycparser` 解析受限的纯 C99 生产模块并执行函数体，而不在 Python 中复制公式。

## D-010：ARM Compiler 6 仅作补充烟雾验证

为获得实际可链接和资源证据，使用 ARM Compiler 6.22、`-Oz -fshort-enums -fshort-wchar`、原 scatter 和闭源库分别构建备份基线与当前源码。该结果可用于同编译器变化对比，但不替代 ARMCC 5 `BUILD_VERIFIED`。

## D-011：指令对比优先保护 Flash 物理路径

首次补充反汇编显示 `WriteFlashAll` 因序列化跨翻译单元调用而变化，因此恢复 `WriteEepromInt/Long` 原赋值体。重建后 `WriteFlashAll` 机器码与基线相同。`SysTick_Handler` 仅私有静态字节偏移改变，函数大小、分支和源体相同，记录为可解释的非时序实质差异。
